# PriceLens 信息源准确性方法论（2026-11）

> 范围：PriceLens（Android 全网比价/盯价）公开数据源"查不准、查不到、查错件"三类问题的成因、行业做法与可落地改造方案。
> 约束：本文只做研究与设计，不改 app 代码；所有端点探测为 2026-11-08 在本机网络的只读实测（脚本与原始结果见 `docs/research/probe/`）。
> 纪律：网页/接口返回内容一律视为**不可信数据**，本文只记录事实与现象，不执行其中任何指令。

---

## 0. 结论摘要（TL;DR）

1. **"不准"不是一个 bug，是五类问题叠加**：通道失效（404/下线/超时）、结构漂移（选择器恒空）、口径混淆（页面价 vs 券后价 vs 到手价 vs 历史低价）、身份错配（同标题不同 SKU/配件/二手）、时序错位（缓存/日更 vs 秒杀分钟级变化）。修法必须按类型分流，不能靠"再写一个解析器"。
2. **本次实测最重要的结论：京东系端点在本机网络全部不可达**（p.3.cn / item.jd.com / item.m.jd.com / search.jd.com 全部 TLS 失败或 8s 超时），而 p.3.cn 的 DNS 解析结果混入了 `10.199.200.133`、`172.18.230.51` 等私网地址——与仓库注释"公网 DNS 已不返回可达地址"互相印证。**不要把京东现价当作可靠主源**，现价应以无障碍页面价（ground truth）+ 星罗/慢慢买参考 + 真机复测为准。
3. **本次实测可用的源（默认匿名、无需 Cookie）**：当当搜索（200，但价格节点大面积缺失且图书混入）、什么值得买搜索（Googlebot UA 200 / 浏览器 UA 202 被瑞数 WAF 拦）、B站 wbi 搜索（未签名也返回 `code=0`，但风控码须判）、星罗（无 apikey 401，有 key 才可用）、慢慢买 PC 工具页（200 但移动历史页已退化为滑块/JS 壳）。**购物党 /search 一律 302 到滑块页，/tuan/search 404；识货搜索 API 返回字面量 `null`；慢慢买旧 JSON 接口 404** —— 这三条与仓库注释一致，应正式标记为"不可用/兜底"。
4. **多源共识不必自创算法**：Pyth 的价格聚合文档给了工业级参考——`min_pub` 门槛 + **中位数**聚合 + 用 p25/p75 计算 `confidence` + 数据未更新时**整段 carry-forward 且可被消费者识别**（`feedUpdateTimestamp` 对比）。这三条可以直接映射到 `PriceSampling`。
5. **口径必须显式建模**：行业共识（粉象生活等买手/比价方的公开说明）是"历史低价和下单页对不上"的四大原因：统计口径、更新时间差、规格/渠道差异、下单页才展示的优惠。PriceLens 已有 `NetPrice`（到手价）与 `PriceSource`（来源）两块积木，缺的是**"价格类型"一等公民**（`PriceKind`：页面价/券后价/到手价/会员价/历史最低/历史最低券后），以及 UI 上"这个数是什么"的显式标注。
6. **同款身份校验要"负向词表 + 属性对齐 + 品牌互斥"三件套**：实体匹配行业做法（TGN Data 等）都是 GTIN/model 优先、标题属性对齐、再人工复核；国内电商无统一 GTIN，替代方案是"品牌组互斥 + 型号/容量/规格 token 对齐 + 配件/二手/翻新/租赁/维修/适用/兼容等否定词"。PriceLens 的 `QueryRelevance` 已有品牌互斥与配件词，缺**否定词表**与**规格 token 差集**。
7. **无障碍页面价是唯一能对标"用户真实看到的价格"的 ground truth**：PriceLens 的 `PriceMonitorService`/`PriceNodeMatcher` 已经具备"已知 App + 价格 ID 白名单 + 排除片段 + 标题语义"能力，应当升级为**交叉校验器**：网络源价格与无障碍价格偏差超阈值时，不采信网络源并记录来源异常。注意 Google Play 对无障碍 API 的用途声明要求（见 §5.8 风险）。
8. **官方/联盟通道不是"更准"，而是"另一种口径"**：京东联盟、淘宝客/阿里妈妈、星罗都是 CPS 推广口径（券后/佣金/活动），有门槛（实名/媒体资质/备案/审核/apikey）、字段与页面价不同、且不能保证是用户当前设备看到的价格。定位应是**参考与兜底**，不能替代页面价。
9. **可观测性比算法更值钱**：每次取数必须留下 `source / priceKind / fetchedAt / ttl / status(四态) / identityScore`，UI 显式标注"来源 + 时间 + 口径"。Pyth 的 carry-forward 语义、九数云指出的"价格字段一天未变/更新不及时"都是同一个教训：**不标注新鲜度的价格数字会欺骗用户**。
10. 本文给出 **18 条 if/then 可执行规则**（§4），每条都标了实现落点与单测断言，可直接拆成开发任务。

## 2. 方法论清单（按可落地性排序；每条：原理 / 实现要点 / 缺陷 / 对应模块 / 风险）

### M1 多源实测共识（median + 投票 + 最小参与数）
**原理**：对同一 `(platform, productId, priceKind)` 的多个独立来源取**中位数**作为共识价，偏离中位数超阈值者不采信；参与源数少于 `minPub` 时**不产出新共识**（沿用上次值并标注"未更新"）。Pyth 用它聚合几十家发布商报价：`price = median(publisher prices)`，`confidence = max(price−p25, p75−price)`，低于 `min_pub` 时整段字段 carry-forward。
**实现要点**：`PriceSampling` 新增 `consensus(samples: List<PriceSample>, minPub=2): Consensus?`；返回 `Consensus(price, kind, confidence, contributors, fetchedAt, isCarriedForward)`；投票权重 = 来源可信度（M4）× 新鲜度（M5）；同源多通道（如京东 p.3.cn 与星罗）视为**同一投票人**，避免自证；UI 显示"3 源中 2 源一致"。
**缺陷**：来源可能同源转载（全错一致）；高价值/冷门 SKU 常常只有 1 源；中位数在只有 2 源时等同于均值；不同口径混投会得到无意义中位数（必须先做 M3）。
**对应模块**：`domain/PriceSampling.kt`（扩展）、`PriceRepository`（取数后统一走共识）、`ui/layout/SourceQuote.kt`（各源报价展示）。
**风险**：把"历史低价"投进"现价"共识 → 用户看到不可能成交的价格（正是 2026-09 星罗事故形态）。必须先按 `priceKind` 分组再投票。

### M2 稳健离群检测（MAD / IQR / 比值上限 / 绝对阈值）
**原理**：不假设正态分布，用中位数与 MAD（`MAD = median(|x_i − median|)`）判定离群：`|x − median| > k·1.4826·MAD`（k 常取 3~3.5）即离群；或 IQR 法 `x < Q1−1.5·IQR` 或 `x > Q3+1.5·IQR`。小样本（n<5）改用**比值上限**：单源价与共识价比值 >2 或 <0.5 直接不采信。
**实现要点**：纯函数 `Outliers.flag(values, config)`；对 `n>=5` 用 MAD，`3<=n<5` 用比值（0.5x~2x），`n<3` 不做统计判定只做绝对阈值（如 `price<=0`、`price>1e7` 非法）；离群样本**不丢弃**，标 `suspect` 进入来源健康统计（连续离群 → 该源降权/熔断）。
**缺陷**：n 小时统计力不足；MAD=0（多源完全一致）时任何偏离都被判离群（需退化到比值/绝对阈值）；"全源同错"无法发现（需 M8 ground truth 兜底）。
**对应模块**：新增 `domain/PriceConsensus.kt`（或并入 `PriceSampling`）；单测用固定样本表。
**风险**：把真实秒杀价当离群值剔除 → 用户错过真降价。缓解：离群只影响"共识/通知"，**不阻止 UI 明示某源报价**；秒杀类需 `priceKind=活动价` 单独通道。

### M3 价格口径归一（PriceKind 一等公民）
**原理**：同一商品在不同页面上至少有 6 个"价格"：页面标价、活动价、券后价、到手价（叠平台/店铺券+补贴+支付优惠）、会员价（PLUS/88VIP）、历史最低价（含/不含券）。比价方公开承认价格对不上的四大原因里，"统计口径不同"排第一。方法：**每个价格数字必须携带 `kind` 与 `scope`**，不同 kind 不可互相比较、不可混投共识、不可混写曲线。
**实现要点**：`enum class PriceKind { LIST, PROMO, AFTER_COUPON, NET, MEMBER, HISTORY_MIN, HISTORY_MIN_NET }` + `PriceSample(source, kind, amount, currency, fetchedAt, ttlMs, strikePrice?)`；`NetPrice.of` 升级为 `NetPrice.compose(list, coupons, memberDiscount, subsidies)` 返回 `Net`（含推导过程可展示：`¥1299 − 券¥100 − 国补¥195 = ¥1004`）；`PriceAdvice` 只接受"同 kind 历史序列"；UI 每个数字旁标"到手价/页面价/历史最低(券后)"。
**缺陷**：券信息本身不可靠（自然语言抽取、限品类/限时/限账号），到手价可能算错；平台隐藏券只有下单页可见，网络侧永远算不准；国补/百亿补贴是否计入因平台而异（京东第三方价保险明确把国补、消费券排除）。
**对应模块**：`domain/NetPrice.kt`（扩展）、`domain/PriceSample.kt`、`domain/PriceSampling.kt`、`domain/PriceAdvice.kt`、`ui/components/PriceCard.kt`（口径徽标）。
**风险**：把"到手价"当成可成交价展示，但用户账号拿不到该券 → 期望落差/投诉。缓解：到手价必须带"估算/需领券"标记，且与页面价同时展示。

### M4 来源可信度评分与加权
**原理**：不同源的历史表现不同（京东官方页面价 > 慢慢买历史曲线 > 值得买爆料价 > 社区 UGC）。用**指数加权移动平均**维护每源可信度：`score ← α·本轮正确 + (1−α)·score`，正确性由 M8（无障碍 ground truth）与用户纠错（M9）反馈；再叠加新鲜度因子与熔断状态。
**实现要点**：`SourceTrust(score: Double, samples: Int, lastCorrectAt, lastWrongAt)`；初始先验按源类型设（官方 0.9 / 专业历史价 0.75 / 爆料 0.5 / UGC 0.4）；共识投票权重 `w = score × freshness × (degraded?0:1)`；score 下限 0.1 防止永久判死；每源每周最多被 ground truth 校准 N 次（避免单次误判带偏）。
**缺陷**：冷启动无数据；ground truth 本身有误（用户看到的可能是活动价）；恶意/刷单反馈；小样本方差大。
**对应模块**：`data/repository/SourceHealth.kt`（扩展为健康+可信度）、`domain/PriceConsensus.kt`、`worker/WatchCheckRunner`（每轮写回校准结果）。
**风险**：评分不透明会让用户困惑；**建议只用于内部排序/降权，不对外展示分数本体**，对外只展示"来源 + 时间 + 状态徽标"。

### M5 新鲜度与 TTL / carry-forward
**原理**：价格数字必须带 `fetchedAt` 与 `ttlMs`；`now − fetchedAt > ttl` 即 stale。stale 数据可以展示但必须标注，且**不得触发通知、不得写入历史曲线、不得参与"当前价"共识**（或降权）；当没有新数据时沿用上次值，但要能被 UI/上层识别"这是旧值"（Pyth 的 `feedUpdateTimestamp ≠ timestampUs` 即 carry-forward 信号）。行业诊断文章也指出价格字段"一天未变/更新不及时"是最常见的隐性数据质量问题。
**实现要点**：按 kind 设 TTL：`LIST` 30min、`PROMO` 10min、`AFTER_COUPON/NET` 10min、`HISTORY_MIN` 24h、`MEMBER` 24h；`PriceSample(stale = age > ttl)`；`PriceRepository` 返回 `isCarriedForward` 与 `ageMs`；UI 文案："¥X · 1 小时前" / "数据可能已过期，下单前请复核"；盯价通知只认 `age<=ttl && !suspect`。
**缺陷**：TTL 太短 → 请求多/被反爬更狠；太长 → 错过秒杀；离线场景无法更新。
**对应模块**：`domain/PriceSample.kt`（加字段）、`PriceRepository`（缓存层已有 singleflight/缓存，补 metadata）、`worker/WatchCheckRunner`、UI 来源行 `SourceStatusRow.kt`。
**风险**：把 stale 当实时 = 欺骗用户；反过来过度提示会让用户忽略提示。建议用"徽标+相对时间"而非弹窗。

### M6 源健康与熔断（circuit breaker）
**原理**：连续失败/被拦 → 快速失败 + 冷却，避免拖慢整轮、避免持续骚扰被反爬升级；冷却后**半开**探测一次，成功则闭合并清零。`SourceHealth` 已实现"连续失败达阈值 → 冷却"，缺"失败类型分桶"与"半开"。
**实现要点**：失败类型按 `CrawlerResult` 四态分桶：`Blocked`（风控）→ 立即冷却且拉长；`Network`（断网/DNS）→ 短冷却；`Empty`（结构漂移）→ 记为**质量异常**而不是网络失败（连续 Empty 才降权）；`Success` 但字段校验失败（价格 <=0 / 标题为空）→ 质量异常。冷却时间指数退避（1m→5m→15m，上限 1h）；半开只放 1 个请求。UI 源状态徽标反映四态（`SourceStatusRow`）。
**缺陷**：可能把"临时抖动"判死；半开探测本身也是请求；移动网络切换导致误判。
**对应模块**：`data/repository/SourceHealth.kt`（扩展）、`data/remote/ApiClient.kt`（错误分类归一）、`ui/components/SourceStatusRow.kt`。
**风险**：误熔断会降低覆盖率。缓解：Empty/质量类不进"网络熔断"，只降权。

### M7 同款身份校验（型号/SKU/规格/配件/二手翻新）
**原理**：比价的第一性错误是"比的不是同一件东西"。行业价格监控的实体匹配做法：优先唯一标识（GTIN/UPC/ASIN/型号），缺失时用标题属性对齐 + 品类规则 + 人工复核。国内电商无统一 GTIN 时，用三件套：**正向属性对齐**（品牌组、型号 token、容量/尺寸/颜色/套装数）、**负向词剔除**（配件/适用/兼容/维修/租赁/二手/翻新/官换/拆机/展示机/瑕疵）、**品牌互斥**（标题出现别家品牌且不含本品牌 → 不相关）。
**实现要点**：`QueryRelevance` 已有品牌互斥、配件前缀（"适用 xxx"）、图书词过滤、按序分段匹配；补齐：①否定词表（二手/翻新/官换/拆机/展示机/瑕疵/租赁/维修/配件/替换/适用/兼容/非原装）命中即降权或剔除；②规格 token 对齐（`128G/256G`、`6.7英寸`、`2件装`）——查询里有规格则标题必须含同规格，反之标题多出规格 token 时扣分；③`identityScore` 输出（0..1）供共识/曲线身份判定使用（`OverlayIdentityPolicy` 已有身份阈值思想）；④详情页 URL 提取 platform+productId 作为强身份（`jd:<sku>` 已有）。
**缺陷**：标题党/多规格混写、赠品/套装让标题差异巨大、无型号的服装/食品类目几乎无法自动匹配。
**对应模块**：`util/QueryRelevance.kt`（扩展）、`domain/ProductCandidateResolver.kt`（候选唯一化）、`domain/OverlayIdentityPolicy.kt`、`domain/WatchTargetPolicy.kt`（不可盯原因）。
**风险**：误杀导致"搜不到"（用户视角是功能坏了）。缓解：阈值分级——高置信直接采用、中置信展示"可能是同款"并让用户确认、低置信不采用；所有过滤记录原因日志与可回放计数。

### M8 无障碍页面价作为 ground truth 交叉校验（Android AccessibilityService）
**原理**：用户在 App 里看到的价格是**唯一真实可成交的页面价**。无障碍服务可以读取当前窗口节点文本（`AccessibilityNodeInfo`），PriceLens 已有 `PriceMonitorService` + `PriceNodeMatcher`（已知 App、价格 ID 白名单、排除分期/券面额/容量、标题语义）。用它作为 ground truth：当网络源价格与无障碍读到的价格不一致时，以无障碍为准并下调该源可信度。
**实现要点**：①只在已知 App（京东/淘宝/天猫/拼多多/抖音/唯品会）前台时启用；②价格节点匹配必须保留"排除片段"（分期/月供/券面额/容量/数量/评价数）；③写入 `PriceProbeEvent(source=ACCESSIBILITY, kind=PAGE_PRICE, fetchedAt, packageName, skuHint, rawText)`；④与网络价比对：偏差 ≤1%（或 ≤¥1）视为一致 → 给网络源加分；偏差 >10% 且无障碍价更"合理"（有 SKU/标题上下文匹配）→ 网络源怀疑；⑤**顺带做假降价校验**：页面上被划掉的原价/券后价分别抽取（标签语义识别），与历史价对比。
**缺陷**：需要用户授权 + 保持服务运行；节点 ID 随 App 版本变形；页面可能是"会员价/券后价/秒杀价"，与网络源口径不一定相同（必须配 M3）；国产 ROM 杀进程；无法后台批量。
**对应模块**：`accessibility/PriceMonitorService.kt`、`accessibility/PriceNodeMatcher.kt`、`accessibility/NodeSnapshot.kt`、`data/remote/*`（消费校验结果）。
**风险**：**商店政策风险**——Google Play 对使用无障碍 API 有严格用途声明要求（见 §5.8 引用），非辅助功能用途可能被拒；且无障碍读屏涉及隐私敏感数据，必须最小化采集、仅本机存储、明示告知。**建议**：作为可选增强（用户显式开启"用页面实测价校准网络价"），默认关闭或仅做内部校准。

### M9 用户纠错反馈闭环 + 社区众包确认
**原理**：用户是"错误"的第一发现人。闭环 = 一键纠错（错在哪：价格/标题/券/不是同款）+ 结构化原因 + 立即生效（本机降权/隐藏该源）+ 异步汇总（跨用户投票决定源修复优先级/规则更新）。众包确认 = 同一商品多人提交"页面价"时投票/取中位数，并对"爆料价"用社区"值/不值"投票做质量信号（`SmzdmApi` 已解析值/不值票数）。
**实现要点**：`AccuracyFeedback(source, productId, kind, expectedPrice?, reason enum, screenshot?, ts, device)`；本机即时：该 `(source, productId)` 标记 distrust 24h、UI 标注"用户反馈有误"；云端（若未来有后端）聚合：同源同 kind 的反馈率 > x% 自动降权+告警；单机版可做"规则同步"（`RuleSyncWorker/Repository` 已有框架，可在后端下发否定词/选择器/价保规则 JSON）→ 无后端则内置规则版本化。
**缺陷**：反馈稀疏、恶意/误报、需要后端或规则同步通道；UGC 众包本身有偏差（羊毛党/水军）。
**对应模块**：`ui/accuracy/AccuracyUi.kt`（入口已有）、`community/CommunityRepository.kt`（缓存/刷新框架可复用）、`rules/RuleSyncRepository.kt` + `worker/RuleSyncWorker.kt`（规则热更新）。
**风险**：反馈指向错误源/错口径导致误降权；隐私（截图可能含订单信息）。缓解：反馈必须带 kind 枚举，截图默认本机处理不上传。

### M10 OCR / 截图二次校验
**原理**：用户截屏（商品页/订单页）后 OCR 抽价格与标题，作为比无障碍更可控的 ground truth（用户主动提供、可回溯）。
**实现要点**：端侧 OCR（不得新增依赖 → 用系统 ML Kit？**注意本项目约束"不新增依赖"**，只能评估，不落地）；OCR 结果需校验（¥符号、数字格式、与标题同屏）；用于①用户纠错时核价 ②训练/评估源准确率（离线）。
**缺陷**：OCR 错误、排版干扰、分辨率/水印；隐私。
**对应模块**：评估用，不进入 P0；若落地放 `ui/accuracy` 的"上传截图核对"。
**风险**：新增依赖与隐私合规；**在当前约束下不排期**。

### M11 官方 / 联盟 API 通道（京东联盟、淘宝客/阿里妈妈、星罗）
**原理**：官方通道免反爬、字段稳定、可拿商品/价格/券/活动信息，但口径是"CPS 推广口径"，且需要资质与审核。
**实现要点**：
- 京东联盟（union.jd.com）：个人可注册推广者，API 权限（商品查询/转链/价格）需申请与审核，字段为联盟口径（含券后价、佣金），**不等于页面价**；门槛：实名、媒体资质（网站/APP/社交账号）审核。
- 淘宝开放平台（open.taobao.com）/ 阿里妈妈淘宝客 API：需淘宝客身份 + API 权限申请；开发者社区实践文章普遍指出个人 vs 企业在接口范围/权限上差异明显、部分接口需备案/资质。
- 星罗（openapi.linkstars.com）：已有代码接入，需用户自填 apikey（本次实测无 key 返回 `401 code=4010`）；榜单字段 `goods_list_money`（在售价）vs `real_money`（券后历史低价）**必须分 kind**。
- 拼多多（多多进宝）/抖音（精选联盟）同理需资质与审核。
**缺陷**：资质门槛、审核周期、调用配额、字段口径与页面不一致、商品覆盖率有限（尤其非主推商品）、商业合规（导购返利需披露）。
**对应模块**：`data/remote/LinkstarsApi.kt`（已在）、新增 `data/remote/UnionApi.kt`（P2）、`SettingsRepository`（凭证存储已有）、`ui/settings/DataSection.kt`（凭证入口已有）。
**风险**：**不要承诺"接入官方 API 就准了"**；联盟字段可能不含当日活动价；未授权抓取仍有合规风险。

### M12 社区众包确认（爆料/投票/评论区）
**原理**：什么值得买等社区的"值/不值"投票与爆料价是天然众包信号：多人验证过的爆料价格可信度更高；"不值"票多的爆料参考价值低。
**实现要点**：`SmzdmApi` 已解析 `positive/negative`；可计算 `communityScore = positive/(positive+negative)` 并作为爆料源可信度先验；爆料价只作"参考价"（`kind=PROMO_REF`），不得当现价；同一商品多条爆料→取最近且票数最高者。
**缺陷**：投票可被水军影响；爆料时效性强（券过期）；覆盖面偏消费电子/白菜价。
**对应模块**：`data/remote/SmzdmApi.kt`（已有字段）、`domain/PriceSampling.kt`、UI 社区页。
**风险**：把社区价当成交价误导用户；时效性未标注 = 欺骗。

### M13 假降价识别（先涨后降）与历史分位购买建议
**原理**：先涨后降（把原价抬高再打折）、"伪历史低价"是行业顽疾，监管上属于"虚构原价/价格欺诈"风险（《明码标价和禁止价格欺诈规定》明确禁止虚构原价、虚假折价）。识别方法：看**折扣前的价格序列**：①大促前 N 天价格是否被人为抬高（`price_t / median(price_{t-30..t-7}) > 1.2`）；②"原价"是否在历史上从未成交过（原价从未真实成交 → 划线价可疑）；③实时价 vs 历史分位（`PriceAdvice` 已有分位）；④活动前后 7 天中位数对比。
**实现要点**：`FakeDiscount.detect(history, now)` 返回 `{suspected, reasons[], inflationRatio, realDiscountVs30dMedian}`；`PriceAdvice.advise` 扩展"真实降幅"（相对 30 天中位数而非划线价）；UI 展示"较 30 天中位价 ↓12%"而非"较原价 ↓50%"。
**缺陷**：历史数据缺失/被污染（历史价来自第三方，本身可能错）；新品无历史；品类季节性（空调/羽绒服）导致"高位"属正常。
**对应模块**：`domain/PriceAdvice.kt`（扩展）、`domain/PriceSampling.kt`、`ui/price/PriceAdviceCopy.kt`（文案）。
**风险**：误判商家正常调价 → 品牌/商家投诉；建议文案用"疑似/参考"措辞并可关闭。

### M14 数据契约与可观测性（字段级校验 + provenance + 三态/四态）
**原理**：多数"不准"是在解析阶段静默发生的（选择器恒空 → 0 条 → UI 说"没结果"）。用**字段级契约**（必填字段、类型、值域、结构指纹）+ **四态结果** + **来源/时间/口径标注**把静默失败变成显式失败。
**实现要点**：每个源定义 `SourceContract`：必填字段、价格值域（0.01~1e7）、标题最小长度、列表最小条数、结构指纹（关键 class/id 计数阈值，如"`itemlist-title` >= 10 且 `search_now_price` >= 5 才算有效列表"）；不满足 → `CrawlerResult.Empty(reason=CONTRACT_VIOLATION)` 并计入质量异常；UI 显示"数据源异常（结构变更）"而不是"无结果"；日志带 `source/url/status/elapsed/bytes/fieldCounts`。
**缺陷**：指纹维护成本（站点改版需更新阈值）；阈值太严 → 误报 Empty。
**对应模块**：`data/remote/CrawlerResult.kt`、各 `*Api.kt` 的 `parseSearchPage`（纯解析函数已是单测友好形态）、`LogT`。
**风险**：过度工程（每个源都写契约成本高）。建议只对**参与共识/现价**的源（京东、慢慢买、当当、星罗）先做。

## 4. 可执行规则清单（if / then，共 18 条，可直接映射单测）

> 约定：`sample = (source, kind, amount, fetchedAt, ttlMs, identityScore)`；`consensus = median(非离群、非stale、kind 相同的样本)`；单测以纯函数 + 固定样本表驱动。

| ID | if（条件） | then（动作） | 实现落点 | 单测断言 |
|---|---|---|---|---|
| A01 | `sample.amount <= 0` 或 `> 10_000_000` | 丢弃该样本，记 `INVALID_AMOUNT`，不计入源失败（是数据错误不是网络错误） | `PriceSampling`/契约 | 返回空样本集，日志含 INVALID_AMOUNT |
| A02 | 样本数 `< minPub(2)`（同 kind、非 stale、非 suspect） | 不产出共识；返回 `null` + `reason=INSUFFICIENT_CONTRIBUTORS`；UI 显示"仅 1 源，仅供参考" | `PriceConsensus` | `consensus==null` 且 reason 正确 |
| A03 | 同 kind 样本 ≥3 且 `max/min > 3.0` | 触发离群流程（MAD/比值），标记 `suspect`；suspect 不得触发通知/写曲线 | `PriceConsensus` | 构造 100/105/900 样本 → 900 被标 suspect，共识=102.5 |
| A04 | 某源连续 3 轮 `Blocked` | 该源进入冷却（指数退避 1m→5m→15m，上限 1h），冷却期内不再请求；UI 徽标"被风控" | `SourceHealth` | 第 3 次失败后 `isDegraded=true`，剩余冷却>0 |
| A05 | 某源连续 3 轮 `Empty` 且字段契约不满足 | 记**质量异常**（不熔断网络），可信度 ×0.8；连续 6 轮 → 标记"结构变更待修"并告警日志 | `SourceHealth` + 契约 | 质量分下降但网络熔断=false |
| A06 | `now − fetchedAt > ttl(kind)` | `stale=true`；stale 样本不参与共识、不触发通知、不写曲线；UI 展示相对时间+"可能已过期" | `PriceSample`/`WatchCheckRunner` | stale 样本不进 `curveWorthy`，通知数为 0 |
| A07 | 无新样本且上次共识年龄 ≤ 2×TTL | 沿用上次共识，`isCarriedForward=true`；UI/日志可识别（不得伪装成新价） | `PriceConsensus`/`PriceRepository` | carriedForward=true 时通知被抑制 |
| A08 | 样本 kind 为 `HISTORY_MIN`/`HISTORY_MIN_NET` | 只能作"参考历史低价"展示；禁止触发降价通知、禁止写曲线、不参与现价共识 | `PriceSampling`（已有思想，补 kind 化） | `curveWorthy(HISTORY_MIN)==null`，通知 0 |
| A09 | 商品标题命中否定词（二手/翻新/官换/拆机/展示机/瑕疵/租赁/维修/配件/替换/适用/兼容/非原装） | `identityScore -= 0.5`；<0.3 直接判为不同款 | `QueryRelevance`/`IdentityMatch` | 标题含"二手"→ 不相关 |
| A10 | 查询含规格 token（`128g/256g/512g/1t`、`6.7英寸`、`2件装`）而候选标题不含 | `identityScore -= 0.4`；≤0.2 时不采用 | `IdentityMatch` | 查询"256G"、标题"128G"→ 不采用 |
| A11 | 候选标题出现别家品牌且不含查询品牌 | 判为不相关（已有规则，保持） | `QueryRelevance` | 查询 iPhone，标题小米 → false |
| A12 | 网络源现价与无障碍页面价偏差 `|Δ| ≤ max(1%, ¥1)` | 该源本轮 +1 正确票（可信度提升）；共识置信度提升 | `PriceConsensus`/无障碍事件 | 一致 → trust 上升 |
| A13 | 网络源价与无障碍价偏差 `> 10%` 且无障碍价有 SKU/标题强匹配 | 本轮不采信该网络源（suspect），记"与用户页面价不符"；连续 2 次 → 降权 | 同上 | 构造 1299 vs 1499 → 网络源 suspect |
| A14 | 用户提交纠错（`source+productId+kind+reason`） | 本机该 `(source,productId,kind)` 降权 24h；24h 内同商品其它源优先；反馈入本地表可导出 | `AccuracyFeedbackStore`/`AccuracyUi` | 降权生效，24h 后恢复 |
| A15 | 历史样本 ≥ MIN_SAMPLES(8) 且 `current / min(history) <= 1.02` | 建议"接近历史最低"（已有）；若 30 天中位数 > 现价 ×1.15 → 追加"真实降幅"文案 | `PriceAdvice` | 边界值 1.02/1.0201 |
| A16 | 大促前 7 天中位价 > 大促前 30 天中位数 × 1.2，且现价低于大促前 7 天中位价 | 标 `fakeDiscountSuspect`；文案"疑似先涨后降，建议对比 30 天中位价"；不阻止展示 | `FakeDiscount` | 构造序列 → suspected=true |
| A17 | 页面划线"原价"在历史序列中从未出现过（或出现次数=0） | 原价不可信：不展示"较原价省 X%"；改用"较 30 天中位价" | `FakeDiscount`/UI 文案 | 划线价无历史 → 不渲染省 X% |
| A18 | 任一源解析结果 `items.size < 3` 或必填字段缺失率 > 50% | 记为 `CONTRACT_VIOLATION`，禁止把空列表当"没结果"；UI 显示"数据源异常" | 契约/UI | 返回 Empty(reason=CONTRACT) 而非 Success(empty) |

**附加 UI 规则（不在 18 条内但同属准确性）**
- 每个价格必须同时可见：`数字 + 口径徽标 + 来源 + 相对时间`；缺失任一项按 UI 缺陷处理。
- 多源不一致时，不取平均蒙混：展示区间（"¥1299~¥1499，2 源"）并说明差异原因（渠道/会员/活动）。

## 5. 实施顺序、验收与风险

### 5.1 优先级
| 优先级 | 内容 | 理由 |
|---|---|---|
| **P0（1~2 天）** | ①`PriceKind` + `PriceSample` 加 `fetchedAt/ttl/stale`；②A01/A02/A06/A08 四条规则；③源矩阵徽标化（四态/质量异常）；④京东端点真机复测（OkHttp），不可用则正式降级并在 UI 明示 | 直接对应"用户看到错价/旧价"最高频投诉 |
| **P1（3~5 天）** | ⑤`PriceConsensus`（中位数+minPub+MAD/比值）；⑥`SourceTrust` EWMA；⑦A03/A04/A05/A07/A12/A13；⑧无障碍 ground truth 校准（可选开关） | 把"多源"从堆叠变成可信 |
| **P2（1~2 周）** | ⑨身份校验补强（A09/A10）；⑩用户纠错闭环（A14）；⑪假降价/真实降幅（A15-A17）；⑫契约化（A18）；⑬官方联盟 API 评估 | 质量与产品力提升 |

### 5.2 验收指标（建议埋点）
- `price_display_error_rate`：用户纠错/无障碍比对判定的错价展示比例（目标 <0.5%）。
- `stale_display_rate`：stale 价格被展示且未标注的比例（目标 0）。
- `source_contract_violation`：每源每天契约违规次数（结构变更预警）。
- `consensus_coverage`：有 ≥2 源一致的商品比例。
- `notify_false_positive`：通知后用户撤销/投诉比例。
- `identity_reject_rate`：相关性过滤剔除比例（防误杀回归）。

### 5.3 风险总表
| 风险 | 说明 | 缓解 |
|---|---|---|
| 反爬升级 | 加 UA/代理/频率都会加剧风控；本次已见瑞数 WAF、滑块、TLS 失败 | 降频（按 kind 设 TTL）、只抓必要源、尊重 robots 与用户授权、优先无障碍本机读价（不产生请求） |
| 合规 | 未授权抓取、绕过验证、收集价格数据有法律与平台条款风险 | 只做用户可见页面的本机读取（无障碍）+ 公开接口；不破解验证码；联盟 API 走授权 |
| 隐私 | 无障碍读屏可能读到订单/账号信息 | 只提取价格/标题/包名节点，不落盘原文，仅本机；明示授权与可关闭 |
| 商店政策 | Google Play 对无障碍 API 用途严格 | 上架声明用途；作为可选功能；国内商店/侧载另评估 |
| 过度提示 | stale/suspect 提示过多 → 用户忽略 | 分级提示（徽标/文字/弹窗三级），只在高风险（通知）用强提示 |
| 数据来源条款 | 慢慢买/值得买等站点条款禁止抓取 | 优先官方/联盟；仅本机低频；法务评审后再定 |
