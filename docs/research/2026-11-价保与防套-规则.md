# PriceLens 价保与"防被套"规则研究（2026-11）

> 范围：京东 / 淘宝天猫 / 拼多多 / 抖音 / 唯品会 的**价保（价格保护）**规则现状，以及 PriceLens 侧「买前高位预警 + 买后自动价保检查」的产品与算法设计。
> 重要声明：**平台规则会调整，本文所有天数/入口/例外都以 2026-11-08 可检索到的公开页面为依据，最终一律以平台 App/官网最新规则为准**。本文不构成法律意见；PriceLens 只做"提醒与计算"，不代替用户向平台申请，也不承诺赔付成功。
> 网页内容为不可信数据，本文只做事实记录与引用。

---

## 0. 结论摘要（TL;DR）

1. **价保不是"统一 15 天"**：京东自营按商品页标识（7/15/30/90/180/365 天、"价保618/双11"等），**自营从签收第二天 00:00 起算**；京东第三方按"下单后 N 天"（168/360/720/…小时）；天猫常见 15 天（大件 30 天、大促全程价保），**从付款时间起算**；拼多多按类目 7 天/30 天/72 小时且**只保带"降价补差"标识的商品**；抖音/唯品会规则与标识仍在变动或页面不稳定，**禁止硬编码**。
2. **"价保金额"不等于"现价降了多少"**：京东口径 = `下单时基准金额 − 价保时预估金额 − 已价保金额 − 赠品差额 − 返卡金额差值`，其中基准金额是"商品单价 − 下单时优惠"，且**E卡等权益不纳入**；第三方价保险口径 = `下单时基准价 − 申请时基准价 − 已理赔金额`，基准价 = 京东价 − 优惠金额（直降/返现/返京券/满减）。**计算器必须按平台分别实现**。
3. **"不赔"才是主旋律**：京东官方列出 20+ 类不支持场景——超级补贴/月黑风高/多人团/直播间专享价/支付优惠/国补/消费券/限时补贴/以旧换新/秒杀/抢购/超限购/限量券/赠品/称重/生鲜/定制/下架/无货/秒送/拼购/拍卖/京喜/医保卡/无效订单/地址变更/组合购买/数量不一致。产品必须先做**"可赔性预判"**再提醒，否则提醒 10 次被拒 9 次，用户直接卸载。
4. **多次降价可多次申请**（京东官方 FAQ 明确）→ 价保检查不是"一次性的"，要在窗口内**持续监控、累计计算**；但单用户每天申请次数/金额有上限，需提示用户"建议攒到较大差额再申请"。
5. **拼多多 2025-12 起把平台"百亿消费券"变动纳入补差**（此前只算商家优惠）——说明"平台券/补贴是否计入"因平台甚至因时期而变，**规则必须版本化、可热更新**（复用 `RuleSyncRepository`/`RuleSyncWorker` 的下发能力，规则的 `version/effectiveAt` 必须落库）。
6. **买后自动价保检查的技术前提是"订单信息"**：PriceLens 没有订单 API，建议**手动录入 + 无障碍辅助识别（可选）**，录入字段最少为 `platform / orderId(可空) / productUrl(或 productId) / 实付价 / 下单(支付)时间 / 价保标识与期限 / 赠品/返卡`。宁可让用户填 30 秒，也不要猜错窗口。
7. **买前"防套"三件套**：①历史分位高位预警（≥80% 分位）；②"距历史最低"与"较 30 天中位价真实降幅"（不用划线价）；③假降价识别（大促前 7 天中位价明显高于前 30 天中位价 = 先涨后降嫌疑）。买前就告知"该商品可价保 N 天"，把价保变成下单决策的一部分。
8. **提醒必须幂等 + 节流**：同一订单同一"可申请金额档位"同一天只提醒一次；窗口剩余 ≤24h 且可申请金额 > 阈值时升级为高优先级；窗口过期立即停止并显示"已过价保期"，不再发任何通知。
9. 本文给出 **20 条 if/then 可执行规则**（§4）与**算法伪代码**（§3），可直接拆成 `domain/PriceProtection.kt` + `worker/PriceProtectionWorker.kt` + `data/local/OrderEntity` 的实现与单测。
10. **风险**：平台规则随时变、价保申请有风控（机器刷补差会被平台处置）、自动申请可能违反平台条款 → PriceLens **只做计算与提醒，跳转平台官方入口由用户操作**；所有文案用"可能可申请/预计可退"而非"一定能退"。

### 1.2 逐平台细则（原文要点摘录 + 出处）

#### 1.2.1 京东（官方帮助中心，可信度最高）

**A. 价保周期（自营 vs 第三方）**（来源：`291-4537`）
- 自营订单（不含厂商配送）：**商品签收前或签收后** 7/15/30/90/180/365 天（**从签收第二天 00:00:00 开始计算**），或价保服务标识约定的时间范围。
- 第三方商家 / 厂商配送订单：**下单后** 7/15/30/90/180/365 天内（从提交订单时间开始计算 **168/360/720/2160/4320/8760 小时**），或标识约定范围。
- 商品具体周期见商品页"价格保护服务标识"；查看路径：商品详情页标题下 / 商品详情页"安心保障"区域 / 我的订单-订单详情-安心保障。
- 标识示例：7天价保、15天价保、30天价保、90天价保、180天价保、365天价保、价保618、价保双11、节日价保等（以实际展示为准）。

**B. 价保金额计算**（来源：`291-4537`）
> 单件价保金额 = 下单时基准金额 − 价保时预估金额 − 已价保金额 − 赠品差额 − 返卡金额差值
- 下单时基准金额 = 以下单时商品单价为基础，扣除下单时的优惠后形成；**E卡等部分款项/权益不纳入价保计算**，可能和订单实付价格不一致。
- 同一订单多次申请时，已价保金额累计扣除；有赠品/返卡需先扣赠品差额、返卡金额差值。
- 差额以**同一账号**申请前后的差额为准；申请时以**下单地址**展示的当前价为准。

**C. 申请入口**（来源：`291-4537`）
- APP：①我的-客户服务-价格保护；②我的订单-服务中心-价格保护；③我的-退换/售后-申请售后-价格保护；④我的订单-申请退款/取消订单时-选择商品降价-价格保护；⑤首页搜索框（价保/保价）-价格保护。
- PC：我的京东-客户服务-价格保护。
- 申请记录：我的-客户服务-价格保护-申请记录（金额/进度/返还方式）。
- 返还路径：微信/储蓄卡/云闪付/白条/小金库/信用卡/QQ支付/数字人民币/Apple Pay/支付宝 → 钱包余额/京东小金库；其他支付方式（超市卡/E卡等）→ 原支付账户/钱包余额；已开专票/数电发票已报销 → 京豆。

**D. 不支持价保的场景**（来源：`291-4537`，原文要点）
- 特殊促销活动：超级补贴 / 月黑风高 / 超级补贴多人团 / 京东直播间专享价 / 支付优惠（支付券、白条券、白条支付立减等）与返现优惠 / 国家补贴 / 消费券 / 政府补贴 / 焕新补贴 / 限时补贴（限时立减、限时折扣、限时折上折）/ 惊喜组合优惠 / 京享礼金 / 以旧换新（含旧机款、旧机补贴）/ 参团活动 / 京补合约 / 换购 / 加价购 / 顺手买 / 秒杀、抢购、超出限购 / 限量发放的优惠券。
- 特殊商品：赠品/含赠品订单、称重售卖商品、生鲜短保品、定制类商品、虚拟商品、已下架、无货不可预订、京东秒送（自营秒送/秒送）、其他页面特殊说明商品。
- 特殊订单：未完成支付、已申请售后/售后换新、拼购/商采/拍卖/指数抄底/到店订单、医保卡支付、含试用品、已取消/已删除/锁定、下单与申请地址不一致、非京东渠道（jd.com/京东APP/京东购物小程序之外）、数量不一致、组合购买导致降价、第三方非在线支付。
- 风控：机器/串通刷补差、非个人生活所需、补差后大量退款、违反平台规则等 → 平台可不予价保。
- 限额：同一用户每天申请次数与金额有上限；累计返还有上限，超过需实名认证。

**E. 多次降价**（来源：`293-558`）："如商品符合价保条件，**多次降价可多次申请价保**。"（2019-11-10 官方 FAQ）

**F. 第三方卖家和价保险**（来源：`293-552`、`962-4181`）
- 第三方商品带"7天/15天/30天/90天价保"标识的参加价格保护（`293-552`）。
- 第三方"价格保护保险"（价保险）：标识为"618价保险/双11价保险/7天价保险/15天价保险/30天价保险"；**指定时间** = 订单支付成功后 7/15/30 天内（168/360/720 小时内）；
- **"同一商品"定义极严**：商品编号、商品品牌、商品规格、商品型号、商品颜色、商品包装、商品销售方式（最小购买单元、单次购买数量、是否有赠品）等属性参数**完全一致**，任何一项变化都不属于同一商品。
- 计算公式：`单品价保险理赔金额 = 消费者下单时基准价 − 申请理赔时基准价 − 价保险已理赔金额`；
  `下单时基准价 = 下单时商品京东价 − 下单时优惠金额（直降/返现/返京券/满减等）`；申请时同理。
- 示例（官方）：下单京东价 1000、优惠 100 → 基准 900；申请时京东价 1000、优惠 200 → 基准 800；可赔 100。
- 其他：价保险理赔款到京东钱包/京豆；一次性补偿规则（买了"买贵双倍赔"就不能重复拿价保险全额，需先扣已获补偿）；下单成功后的支付优惠/返现差价不赔；订单未出库延后支付，取消则自动作废；价保成功后系统可能作废用户新领的券。
- 价保险"不支持场景"与自营价保基本一致，另加：直播间专享价、超级补贴、月黑风高、多人团、支付优惠、消费券/国补等（`962-4181` 有更细的逐条清单）。

**G. 30 天自动价保（自营）**（来源：`292-4272`）
- 商品带"30天自动价保"标签；**签收前或签收后 30 天内**（厂家/供应商发货商品为**下单后 30 天内**）系统定期监控前台京东价，识别到降价自动退差（京券/京豆等），无需手动申请；同时用户也可在 30 天内自主申请价保（我的-客户服务-价格保护）。
- "订单实际的价保时效以当时下单的时效为准"。

#### 1.2.2 天猫 / 淘宝（官方价保页存在，细节以官方为准）

- 官方价保说明页：`pages.tmall.com/wow/act/22351/priceprotection`（本次实测 200，可达；正文由前端渲染，未取到纯文本）。
- 社区整理（淘江湖，2026-06，**非官方原文，仅作交叉验证**）：
  - 常规服饰/日用多为 **15 天价保**；冰箱空调数码等大件普遍 **30 天**；618 活动商品"全程价保"；价保有效期标注在商品详情页。
  - **计费时间以实际付款日期为准**（与确认收货/签收无关）。
  - 可保品类：美妆、家居日用、品牌家电、服饰鞋包等实物；**虚拟/话费、鲜花生鲜、私人定制、直播间限时秒杀、百亿补贴专属特价不在价保范围**。
  - 差价核算：系统比对**同店铺、同规格型号**实时售价；**跨店满减、店铺通用优惠券**带来的降价计入；**新人专属券、单品定向大额隐藏券不计入**。
  - 入口：天猫 APP-我的-官方客服（88VIP 专属客服）-输入"价保"-价保中心-"一键价保"；或订单详情-订单保障-"申请价保"。
  - 社区还提醒：系统自动比价可能漏算，需留存下单实付截图/当前售价截图，走售后/人工客服/12315 三级补救。
- 淘宝（非天猫）亦有"价保中心"能力，具体入口与规则以 App 内展示为准；产品实现上统一按"商品页价保标识 + 平台规则版本"处理。

#### 1.2.3 拼多多（"降价补差"，2025-12 规则调整）

- 触发条件：购买**标注"降价补差"标识**的商品（商家开通"价格保护"营销工具后自动适用），在服务期内发现**同一商品**拼单价扣除**商家优惠与平台"百亿消费券"**后的实际支付价低于原订单价 → 可申请差额退款。
- 服务期：**水产肉类、新鲜蔬果及熟食类 72 小时；大家电 30 天；其他类目 7 天**。
- 2025-12 调整：把平台发放的"百亿消费券"纳入降价补差计算范围（此前仅商家优惠）；活动商品也纳入价保范畴；退出"百亿补贴"等促销不影响已支付订单。
- 例（报道原文）：拼单价 50、商家优惠 5、8 折消费券 → 实付 36；服务期内商家优惠变 8、消费券 7 折 → 新价 29.4 → 可退 6.6；但下单时未用消费券只实付 45 的，则只按商家优惠部分计算退 3。
- 入口：以拼多多 App 订单详情/客服提供的"申请补差"入口为准（本次未在公开网页抓到入口说明，**实现时不要假设路径**）。
- 来源：正观新闻/亿邦动力 2025-12-03；网经社 100ec《拼多多更新价格保护规则 活动商品均适用"降价补差"》。

#### 1.2.4 抖音电商（规则处于变动期，禁止硬编码）

- 来源：`school.jinritemai.com/doudian/web/articlev0/aJ3dxLdagHPG`（新增公示）、`.../aJAWDkwcd1NL`（废止公示）。

### 1.3 "可赔性预判"通用清单（跨平台，用于买后检查）

> 平台细节不同，但判断顺序可以统一：**先看窗口 → 再看商品/活动是否在保 → 再看降价归因 → 最后算金额**。

1. **窗口**：`now ∈ [起算点, 截止点]`；起算点按平台（京东自营=签收次日 0 点 / 京东第三方=支付成功 / 天猫=付款时间 / 拼多多=服务期起点）。
2. **商品在保**：有价保/价保险/降价补差标识，或订单页显示"申请价保"按钮；无标识 = 大概率不可赔（仍可引导用户查看）。
3. **商品状态**：未下架、有货可预订、未超限购、非赠品/称重/生鲜短保/定制/虚拟/秒送/拼购/拍卖/商采/到店/医保卡/试用品。
4. **订单状态**：已完成支付、未申请售后、未取消/删除/锁定、地址与下单一致、数量一致、非组合购买、渠道为官方 App/网站。
5. **降价归因**（最难）：是"京东价/页面价"降了，还是券/补贴/支付优惠/会员价变化？
   - 京东：只认京东价下降；国补/消费券/支付优惠/直播间/秒杀/超级补贴等一律不赔（第三方价保险同）。
   - 拼多多：商家优惠 + 平台百亿消费券变动都算（2025-12 起）。
   - 天猫：跨店满减/店铺通用券算，新人券/隐藏券不算（社区整理）。
6. **金额计算**：按平台公式（见 §3.2），`max(0, 应退)`；差额 ≤ ¥1 视为噪音不提醒。

### 2.2 买后：自动价保检查（`PriceProtection` 新模块）

**用户流程（目标 ≤30 秒录入）**
1. 用户下单后（或从无障碍检测到"支付成功/订单详情"页面时提示）→ 点击"加入价保跟踪"。
2. 录入：平台、商品链接/标题、实付金额、支付时间、价保标识与天数（默认值按平台给，用户可改）、是否有赠品/返卡/E卡。
3. 系统计算截止日，展示："价保到 12-08 23:59，之后每天帮你查一次价格"。
4. 每日（或每 6 小时，按平台规则与电量策略）检查现价 → 计算预计可退金额 → 差额 > 阈值时提醒："京东价已降至 ¥1,199，预计可退 ¥100，价保剩 2 天，去申请"。
5. 用户点击 → 跳转平台 App（deep link 或引导路径文案），**申请动作由用户完成**。
6. 用户回填"已申请/被拒/已到账" → 关闭或进入累计模式。

**关键设计约束**
- **不硬编码规则**：平台规则以 `RuleVersion` 形式存本地（`version/effectiveAt/source`），启动时校验过期则提示"规则可能已更新"；有网时 `RuleSyncWorker` 拉取最新 JSON。
- **订单信息最小化**：只存计算必需字段；不存支付账号、不存订单截图（除非用户主动用于纠错且仅本机）。
- **检查节奏**：价保期间默认每 24h 一次（可降到 6h，大促最后 3 天加密），避免反爬升级与耗电；复用 `WatchCheckRunner` 的轮次框架或独立 WorkManager（建议独立，避免污染盯价统计）。
- **幂等提醒**：提醒记录 `(orderId, 金额档位, 日期, 类型)` 唯一；同日同档位不重复。
- **诚实失败**：查不到价/被风控 → 显示"今天没查到价，明天再试"，**不得显示"没有降价"**。
- **合规**：不代申请、不自动下单/退款、不绕过平台风控；提醒文案带"以平台审核为准"。

## 3. 算法与伪代码（可直接实现）

### 3.1 窗口计算

```kotlin
data class ProtectionRule(
    val platform: Platform,          // JD_SELF / JD_3P / TMALL / PDD / DOUYIN / VIP
    val windowDays: Int?,            // 7/15/30/90/180/365；拼多多类目另算
    val windowHours: Int?,           // 168/360/720...（京东第三方/拼多多生鲜）
    val startAnchor: Anchor,         // SIGNED_NEXT_DAY / PAID_AT / ORDER_AT / SERVICE_START
    val ruleVersion: String,
    val sourceUrl: String
)

/** 返回 null = 规则不可判定（必须让用户确认，不得猜） */
fun protectionDeadline(order: Order, rule: ProtectionRule): Long? {
    val start = when (rule.startAnchor) {
        Anchor.PAID_AT       -> order.paidAt
        Anchor.ORDER_AT      -> order.orderAt
        Anchor.SIGNED_NEXT_DAY -> nextDayStart(order.signedAt ?: return null) // 签收次日 00:00:00
        Anchor.SERVICE_START -> order.serviceStartAt ?: order.paidAt
    }
    return when {
        rule.windowHours != null -> start + rule.windowHours * 3_600_000L
        rule.windowDays != null  -> endOfDay(start + rule.windowDays * 86_400_000L) // 含当天
        else -> null
    }
}
```

**注意**：京东自营"签收后 N 天"依赖**签收时间**，PriceLens 拿不到物流签收 → 默认让用户填"签收日期"，未填则按"下单/支付时间"给一个**保守下界**并显式提示"可能少算 N 天，请以订单页为准"。这是"宁缺毋滥"原则的体现。

### 3.2 可申请金额计算（按平台分派）

```kotlin
/** 京东自营（官方口径） */
fun jdSelfRefund(order: JdOrder, currentListPrice: Double, currentPromo: Double): Double {
    // 下单时基准金额：商品单价 - 下单时优惠（E卡等不纳入）；此处以用户录入的"下单基准"或实付近似
    val baseAtOrder = order.baseAmount            // 用户录入/由实付+已知优惠推导，缺省=实付
    val baseNow = currentListPrice - currentPromo // 申请时预估金额
    val already = order.refundedAmount
    return maxOf(0.0, baseAtOrder - baseNow - already - order.giftDiff - order.cardDiff)
}

/** 京东第三方价保险（官方口径，与自营略有差异） */
fun jdThirdPartyInsurance(order: JdOrder, currentJdPrice: Double, currentDiscount: Double): Double {
    val baseAtOrder = order.jdPrice - order.discountAtOrder
    val baseNow = currentJdPrice - currentDiscount
    return maxOf(0.0, baseAtOrder - baseNow - order.insurancePaid)
}

/** 拼多多（2025-12 起：商家优惠 + 百亿消费券都计入） */
fun pddRefund(order: PddOrder, currentPinPrice: Double,
              currentMerchantDiscount: Double, currentPlatformCoupon: Double): Double {
    val paid = order.actualPaid                          // 下单实际支付
    val nowPaid = currentPinPrice - currentMerchantDiscount - currentPlatformCoupon
    return maxOf(0.0, paid - nowPaid)
}

/** 天猫（跨店满减/店铺通用券计入；新人券/隐藏券不计入） */
fun tmallRefund(order: TmallOrder, currentPriceWithEligibleDiscounts: Double): Double =
    maxOf(0.0, order.actualPaid - currentPriceWithEligibleDiscounts)
```

**统一注意**：任一输入缺失（如拿不到"下单时优惠拆分"）→ 返回 null 并提示"数据不足，无法预估，请到订单页查看"，**不要用 0 兜底算出虚假金额**。

### 3.3 检查与提醒（幂等 + 节流）

```kotlin
fun evaluate(order: Order, rule: ProtectionRule, now: Long,
             current: PriceObservation?, notifyState: NotifyState): Decision {
    val deadline = protectionDeadline(order, rule) ?: return Decision.NeedsUserConfirm("规则无法判定")
    if (now > deadline) return Decision.Closed("已过价保期")
    if (current == null || !current.fresh) return Decision.Silent("今天没查到价，明天再试") // 诚实失败
    if (!current.isEligibleKind) return Decision.Silent("当前降价来自活动/券，按规则大概率不可赔")
    val refund = computeRefund(order, current) ?: return Decision.NeedsUserConfirm("金额无法预估")
    if (refund < maxOf(1.0, order.actualPaid * 0.005)) return Decision.Silent("差额太小")
    val closing = deadline - now <= 24 * 3_600_000L
    val bucket = if (refund >= 50) ">=50" else if (refund >= 10) "10-50" else "<10"
    val key = "${order.id}|$bucket|${dayOf(now)}"
    if (notifyState.sentKeys.contains(key)) return Decision.Silent("今天已提醒过")
    return if (closing) Decision.NotifyHigh("最后一天！预计可退 ¥${fmt(refund)}")
           else Decision.NotifyNormal("预计可退 ¥${fmt(refund)}，价保剩 ${days(deadline-now)} 天")
}
```

fun preBuyAdvice(history: List<Double>, current: Double, promoContext: PromoContext): PreBuyAdvice {
    val advice = PriceAdvice.advise(current, history)          // 已有：分位 + 接近历史最低
    val pct = PriceAdvice.percentile(current, history)          // 已有：0..100
    val low = history.filter { it > 0 }.minOrNull()
    val median30 = median(history.takeLast(30))
    val inflation = FakeDiscount.inflationRatio(history)        // 大促前7天中位 / 前30天中位
    return PreBuyAdvice(
        percentile = pct,
        highPositionWarning = pct != null && pct >= 80,
        distanceToLowestPct = low?.let { (current - it) / it * 100 },
        realDiscountVs30dMedianPct = if (median30 > 0) (1 - current / median30) * 100 else null,
        fakeDiscountSuspect = inflation > 1.2,
        protectionHint = promoContext.protectionDays?.let { "支持 ${it} 天价保" }
    )
}

## 4. 可执行规则清单（if / then，20 条，可直接映射单测）

> 约定：`order` 含 `platform/paidAt/orderAt/signedAt?/actualPaid/protectionDays?/protectionHours?/giftDiff/cardDiff/refundedAmount`；`rule` 来自 `PriceProtection` 规则表（版本化）。

| P13 | 可申请金额 ≤ max(¥1, 实付×0.5%) | 不提醒（噪音阈值） | refund=0.9 时 Notify=0 |
| P14 | 当前价来源为 stale / suspect / 参考价（历史最低、券后历史低价） | 不计算、不提醒；显示"今天没查到可信现价" | Notify=0，不误报 |
| P15 | 剩余窗口 ≤ 24h 且 可申请金额 > 阈值 | 发**高优先级**提醒（"最后一天"），其余情况普通优先级 | closing 分支判定 |
| P16 | 同一 `orderId + 金额档位 + 日期` 已提醒过 | 不再提醒（幂等） | 二次调用 Notify=0 |
| P17 | 窗口内多次降价 | 允许多次评估/提醒，但累计计算 `− 已价保金额`；提示"同一天多次申请可能有次数上限，建议金额较大时申请" | 第二次 refund = 第二次差额 − 已退 |
| P18 | 价保截止日已过 | 关闭跟踪，UI 显示"已过价保期（X 天窗口）"，不发通知 | 过期后任何调用 Notify=0 |
| P19 | 买前：历史样本 ≥8 且 当前分位 ≥80% | 显示"当前处于历史高位，建议等等/设目标价" | percentile=85 → highWarning=true |
| P20 | 买前：大促前 7 天中位价 > 大促前 30 天中位数 ×1.2，且现价低于前 7 天中位价 | 显示"疑似先涨后降，划线价不可信"，并改用"较 30 天中位价"展示降幅 | 构造序列 → fakeDiscountSuspect=true |

**补充实现规则（非 if/then 但必须遵守）**
- 规则表每条必须带 `platform + ruleVersion + effectiveAt + sourceUrl + verifiedAt`；**规则过期（verifiedAt 超过 180 天）时 UI 标注"规则可能已更新"**。
- 金额/日期计算全部用整数（分/毫秒）避免浮点误差；金额展示保留 2 位小数。
- 所有通知文案必须带"预计/可能/以平台审核为准"，不得写"一定能退"。
- 单用户提醒频率上限：每 24h ≤3 条价保类通知；同订单 ≤1 条/天。

## 6. 风险与合规

| 风险 | 说明 | 缓解 |
|---|---|---|
| 规则变动 | 天数/入口/例外随时调整；抖音规范出现废止公告；唯品会页面跳走 | 规则版本化 + `verifiedAt` + 规则同步；不确定时不让用户依赖自动化 |
| 风控/封号 | 平台明确禁止"机器刷补差"；自动申请可能触发风控 | PriceLens 不代申请、不自动提交；仅提醒 + 跳转官方入口 |
| 计算争议 | 基准价/优惠拆分/赠品/返卡复杂，预估与平台实际不一致 | 文案用"预计"，展示计算公式与假设；请用户以订单页为准 |
| 订单隐私 | 订单号/实付/地址敏感 | 最小化存储、仅本机、不默认导出；备份时脱敏 |
| 反爬 | 价保检查要查现价，公开源被封（见准确性文档实测） | 复用降级/熔断；查不到就诚实说"没查到"；优先无障碍本机读价 |
| 商店政策 | 通知/后台/无障碍权限 | 遵循已有权限与通知策略；价保提醒走普通通知渠道，不滥用高优先级 |
| 误导性文案 | "已省/必退"引发投诉 | 统一文案规范（预计/可能/以平台审核为准），审核文案表 |
