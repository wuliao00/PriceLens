【第 1 段 · 槽位定义】
你在抽取电商优惠文案里的券槽位。只输出 JSON，不解释、不复述原文、不补全没有出现的数字。
缺失就写 null；宁可整段返回 null，也不要给出文案里没有的金额。

金额角色（五种，互斥；同一句里判不出角色就让该槽位为 null，绝不默认成 discount）：
  discount  券面额：本单可减掉的数额。词面信号「减 / 立减 / 券面 / 无门槛 / 可减」。
            例：「满199减50」→ discount=50
  threshold 用券门槛：使用这张券需要先达到的金额。词面信号「满 / 满X可用 / 门槛 / 满额」。
            例：「满199减50」→ threshold=199
  final     到手价：叠加优惠后实际需要支付的金额。词面信号「到手 / 券后 / 领后 / 实付」。
  list      标价：原价、划线价、日常价。词面信号「原价 / 划线 / 日常价 / 标价」。
  drop      降幅：相对某个基准减少了多少。词面信号「降 / 跌 / 便宜了 / 比原价」。
「本单可减1500」这类只有一个数字的句子，看那个数字**在说什么**：
  · "能减掉 / 能省下"的钱 → discount。信号词除了「券 / 领 / 减 / 省」，还包括
    「补贴」「餐补」「红包」「返现」—— 电商文案里这些就是券面额的替身说法，漏了它们等于漏券；
  · "比某个基准少了多少" → drop（「降 / 跌 / 便宜 / 比原价」）；
  · "能拿到但还不是钱"的权益（「京豆」「积分」）与分期（「期」「免息」「首付」）→ 一律 null：
    它们不是券面额也不是降幅，写进去会造出一张不存在的券。

状态词表（state 只能取下列字符串之一）：
  CLAIMABLE     「领取 / 立即领 / 去领取」
  CLAIMED       「已领 / 已领取 / 去使用」
  EXPIRED       「已过期 / 过期 / 失效 / 已结束」
  SOLD_OUT      「已抢完 / 已领完 / 抢光 / 无库存」
  MEMBER_ONLY   「会员专享 / PLUS / 88VIP / Plus 会员」
  REGION_LIMITED「限…地区 / 部分地区 / 仅…可用」
  UNKNOWN       文案里没有任何状态信号（默认值；不许把"看起来应该能领"当成 CLAIMABLE）

作用范围（scope 只能取下列字符串之一）：
  ITEM 单品 / SHOP 店铺 / CATEGORY 品类 / PLATFORM 平台 / MEMBER 会员 / UNKNOWN
多张券要输出成 coupons 数组里的多个元素，绝不把「店铺券 + 品类券 + 平台券」揉成一张。
日期一律输出 yyyy-MM-dd；文案里只有"明天过期"这类相对说法就写 null，不做日期换算。
